# V5 协作成本与 0.32.0 改进

采样：2026-10-10 15:18—21:06（Asia/Shanghai），原 Leader 与同项目直接子会话39个上下文。只读公开 token 计数及工具事件元数据，累计计数去重，不读取推理内容。该时段跨多个插件版本，不代表0.32.0的部署后测量。

| --- | ---: |
| 全团队 | 114,728,953 |

113次等待关联调用的缓存输入11,988,096、新增输入112,713、输出44,308；约占团队累计处理量10.6%、Leader处理量28.4%。这里是事件关联统计，不是精确因果归因或账单估算：缓存处理与新增输入价格不同，部分查询必要，也不能把所有返工都算浪费。Leader平均每次约102,709输入 token，因此即使空等待结果很短，模型仍反复处理大上下文。

新目标派发的32次成员创建均使用 fork_turns=none，没有发现继承整个 Leader 历史作为主要成因。同任务内长执行和大工具输出仍累积：成员工具输出约512万字符，其中239条超过6000字符。0.32.0保留原生输出1200 token、模型单批6000字符及源文件/日志分页协议，直接宿主命令仍不能由插件强制截断。

0.32.0增加跨调用语义 waitCursor，进度保存不再在等待边界触发协调读取；超时返回可复用 continuationArgs，不配套团队/收件箱/schema读取。默认55秒等待，functions.exec yield设置60秒避免工具中途返回多一次模型往返。阶段交接建议从90000输入/50次命令提前为60000输入/30次命令，只在完成边界交接并保存决策、验证及剩余工作，每任务仍最多3次，不能自动清空执行中会话或因连接失败重建。

初始化命令关联、旧准备记录提示和限定原声明输入根解决重复登记卡点，已有审核结果只重试插件门禁，不重派审核或产品测试。V5原后端4条检查的只读预检均匹配，原 manifest 580项文件哈希和提交候选一致，原团队文件未修改。这不等于已经补登记或完成后端独立复审。

宿主仍只有有界等待，插件不能静默唤醒结束的 Leader，空闲模型往返无法全部消除。不能用回归夹具声称固定 token 节省比例；需要新版真实运行数据验证效果。原始采样与恢复输入保留在本地 evidence 目录，不包含在插件发行包。
