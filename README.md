# codex-agent-team

## 0.28.0 执行观察与状态稳定性

V5 原生记录复现了上下文压缩期间公开活动停更超过 60 秒、随后继续执行的情况。记录过期显示“执行记录待更新”，并保留任务已派发状态；关联失败、时钟异常或无法核实的状态仍单独提示。连接暂时失败仅在原有效期内复用同一任务、attempt、线程和轮次的活动证据，不更新证据时间或延长有效期；成功读取后清除临时提示。已确认终态、业务进度与完整历史继续保留。

原生生命周期观察补充 MCP 工具与上下文压缩完成的公开事件元数据，只读类型、身份与时间，不读取工具结果、压缩内容或推理。面板统一任务、成员与执行历史的状态说明；记录延迟不授权验收、结算、重派或重复运行。

## 0.27.0 操作回执与批量预留

0.27.0 将 Leader 操作的成功回执改为精简协调状态和受影响任务，派发、消息、标题等操作包完整保留；需要显示预览可显式 responseView=summary。面板与完整证据格式保持，原历史不改写。批量就绪判断不复制历史交付与日志，并为同一岗位只预留一个任务，继续核对并发、共享资源、写入范围和依赖。

## 0.26.0 问题关闭证据与状态查询

独立审核的问题关闭证据支持非空文字或非空文字数组，完整审查原文保留，账本按原顺序保存全部证据和关闭历史。空项、对象或缺失证据仍拒绝；身份、轮次、严重性和验收门禁保持。升级后旧格式异常可用原证据重试，不重复审核或测试。source-only 后续 NOT_RUN 仍须原 Leader 明确分类，合同通过不能代替产品和团队最终验收。

任务查询只返回状态与当前轮次摘要，避免把历次提示、交付和完整日志装入一次响应；原始证据按选定任务分页读取。

## 0.25.0 V5 流程与读取优化

推进默认返回处理变化、最新版本、下一步动作与完整派发包，省去成功后的重复查询；推进末尾不再二次观察全队，派发预算与终态结算仍独立核实。按任务读取证据替代默认全历史入口，工具参数说明按操作与插件版本复用，常用技能说明压缩，细则按需读取。

面板提示原生会话缺少任务登记，提供只读明细；不猜测任务归属、自动验收或重跑。初始化会话按已绑定成员计成本，避免误报。用量分别展示缓存输入、新增输入、输出，预算仍按累计处理量；这不等于账单/账号限额计量。面板与连接版本不一致会提示重新加载。


## 0.24.0 审核通过直接登记

独立审核角色返回当前交付的 PASS 后，settle/advance 在同一次保存中校验真实轮次、独立身份、合同与条件覆盖、宿主命令、严重问题和声明输入指纹；通过直接登记验收并解锁下游。Leader 仅处理具体异常与团队最终结项，普通通过不再二次审核。中断、审查原文和历次验收回执保留；重复通知不重登记或重验。

最终结项默认复用已验收 integration 合同的有效证据，只读核对当前声明输入内容，不运行测试。单项测试与 source-only 证据不替代整体验证。文件或声明输入变化、旧轮次缺少可靠指纹、证据缺失均保留为异常，不猜测通过，也不为补记录重跑已完成工作。指纹覆盖声明的项目文件；外部环境与未声明输入变化仍需要明确判断。新版数据设置 0.24.0 写入保护，旧连接不可覆盖。

## 工作方式

- 团队确认：新团队先确认目标、成员和职责，确认后 Leader 拆分具体任务与独立审查，无需逐项确认；支持面板编辑或聊天确认；修改后旧确认失效。明确“直接做”可立即执行，普通追加沿用授权；新增岗位、扩大范围和提高预算单独确认，原团队继续运行。
- 同一项目保留一个团队，新任务追加给现有成员；需要新岗位时直接追加成员，重建由用户主动触发。
- 使用 `add_team_members` 追加岗位（活跃人数最多 8），按需模式等首项任务就绪再创建；先用 `add_team_tasks` 分配任务。空闲且无未完成任务的成员可 `remove_team_member`，记录仍保留；`reassign_team_task` 改派等待/阻塞任务，旧轮次归属和重试预算不变。
- 岗位与当前执行会话一对一，命名采用「项目-角色」；已结算任务之后创建干净会话，原线程保留用于历史审计。
- 新团队默认按需创建成员，首个就绪任务携带完整交接包；后续复用同一原生线程。已有团队保留原启动方式。
- 初始面板支持成员和目标编辑，自动读取宿主模型及档位；具体任务在组建确认后拆分，扩展面板保留任务和依赖编辑；并发与预算按需展开，保存后重新确认版本。
- 停止覆盖初始化轮次：stopping → 核实实际终态 → halted；明确原因才能恢复，重试任务单独选择，历史与预算保留。
- Leader 拆解、派发、停止、处理异常与最终结项；普通独立审核由插件校验登记；真实成员可领取自己的就绪任务、报告进度和暂存交付，宿主终态仍须核实。
- 成员共享当前项目，按任务按需读取，不复制完整项目，没有 128MB 快照启动门槛。
- 任务预留、执行、提交、独立审查、最终验收分别记录，历史轮次不会冒充当前交付。
- 可声明阶段、写入/排除范围、验证命令与目标覆盖合同；需求独立验收后再实施。合同验收要求逐项 PASS 和宿主记录的成功命令；改动范围根据成员申报核对，不宣称自动发现所有文件改动。
- 可选择 `autoRepair`，由 Leader 确认退回后生成修复任务和独立复审，重定向下游依赖并保留原证据。问题 ID 跨轮追踪，严重问题需独立证据关闭；审查轮次超限暂停并升级给 Leader。
- 状态先显示、详情后台加载；面板预览限制 256 KiB，完整证据按需读取。实际执行中轮询目标间隔 250ms，已结束待接收的执行降为 1s。任务标签统一编号，依赖卡片 160×76px。
- 原生会话导航使用宿主 openLink 和已验证的 codex 会话深链接；不依赖模型或消息能力。失效请求不打开旧目标，未绑定执行的任务不借用成员的其他会话。宿主接收链接与实际页面呈现分别记录。
- 执行完成前显示公开进度、命令输出和按轮次统计的 token 用量；不会展示隐藏推理。
- 成员持久收件箱、接续包、重试上限和有界工作流由 Leader 控制，工具回执与已读分别记录。
- 支持完整任务模板或仅保存岗位与约束的动态规划模板；宿主模型目录验证显式路由，默认档位随计划冻结。
- 合同修订记录前后值与版本，使旧下游证据失效；已通过验收的合同冻结。压缩前置摘要，保留完整验收条件。
- 写入成员可选择 Git worktree；已独立验收候选经冲突预检后暂存合并，由 Leader 验证并提交。
- 任务号/状态搜索、公开报告导出、时延诊断和校验分卷保留长团队历史。

## 开发

需要 Node.js 22+，打包需要 Python 3，浏览器检查使用 Chrome。

```powershell
git clone https://github.com/wapearoudy/codex-agent-team.git
cd codex-agent-team
npm ci
npm run build
npx playwright install chrome
npm test
npm run validate
npm run package
```

构建输出到 `plugins/team-workspace-probe/dist/`，ZIP 输出到 `artifacts/`，生成文件不提交。GitHub Actions 在 Windows 上执行构建、回归、校验和打包。

## 本地使用

插件身份为 `team-workspace-probe`。构建并通过检查后运行 `node scripts/install-plugin.mjs`，登记本地来源并调用官方安装命令。已有来源会保留备份，不直接修改缓存或强制重启宿主。详细步骤见 [开发与安装说明](docs/DEVELOPMENT.md)。

Windows 默认发现当前用户安装的官方 Codex Desktop 可执行文件；自定义安装位置可设置 `TEAM_WORKSPACE_CODEX_BINARY`。仓库不包含开发者本机路径、登录信息或真实团队记录。

## 实际边界

执行由 Leader 所持有的原生协作工具控制，MCP 服务不能替代这些工具。视图读取宿主持久化快照，轮询间隔不是端到端时延承诺。成员写入范围属于任务约束和冲突调度，不替代文件系统沙箱。

浏览器/协议检查与真实 Desktop 原生执行分别验证；自动检查通过不代表未执行的宿主联调已经通过。原生会话导航不支持指定轮次锚点，历史轮次在面板中回看。

见 [架构与数据边界](docs/ARCHITECTURE.md)、[开发与安装说明](docs/DEVELOPMENT.md) 和 [插件使用协议](plugins/team-workspace-probe/skills/team-workspace/SKILL.md)。

## 0.30.0 工作目录与历史验证关联

原生命令保留真实工作目录及 commandId，正确对应合同中的显式 cd。新增 reconcile_team_verification：预览并核对当前候选、同一任务中断链、宿主终态与历史输入闭包，追加可复用回执；原报告、旧 null 和全部中断/审查记录保持原样。准备长命令时保存执行前输入指纹；同 requestId 重试不覆盖旧指纹。已有独立 PASS 只重试插件门禁，成功后直接解锁后续，不重审或重跑。

不会从复杂脚本猜测子命令，不补造退出码，不把当前必需的 BLOCKED/FAIL/NOT_RUN 改成 PASS。合同之外明确的未来 NOT_RUN 说明保留，不能替代后续任务或最终验收。补登记的数据设置 0.30.0 写入保护；跨 attempt 和已验收历史不可覆盖。详细输入证明格式见技能的“历史验证关联与结果复用”。

## 0.31.0 团队流程系统修复

统一当前合同与后续检查归属：普通审核、显式验收与历史原生登记共用范围规则；执行任务可保留有明确后续合同的 NOT_RUN 说明，不将当前失败或缺失检查放行。旧审核 PASS 的登记失败可通过 reconcile_team_review 预览并原位补登记，保留报告、检查、拒绝与中断历史，避免无意义的二次审核。

命令验证使用最后一次匹配的宿主结果，当前失败/未知不能被历史成功覆盖；阶段复用核对工作目录。停止期间登记不恢复执行状态；保存审核恢复要求原控制已恢复。批量推进返回真实部分成功与异常，失败的 terminal 交付缓存具体原因，不反复自动接收；原失败记录保留。场景回归覆盖正常执行、异常和恢复路径；真实业务核对记录仅保存在本地。

## 0.31.1 跨平台发布修复

验证目录按原生路径自身的 POSIX、Windows 盘符或 UNC 语法解析，避免服务器系统改变历史目录身份；不同盘符、共享目录与未知盘符相对路径不匹配。Windows 的 POSIX 命令准备仍明确提示使用原生命令输出预算和日志选项。补充路径与平台回归，面板验证原证据时间不被改写，事件等待测试留出持久保存时间。
