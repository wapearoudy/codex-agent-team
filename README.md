# codex-agent-team 0.40.57

0.40.57 强制核对原生启动参数，按当前任务合同限定独立审核范围，并支持空启动失败后的安全恢复绑定。原生会话刚创建但尚未落盘时，在可信时间范围内等待，不重复派发或提前授予权限。例行推进保留游标并处理并发登记；原报告、失败、中断与验证证据全部保留。

同一任务的有效验证结果可在核对候选及完整输入未变化后复用；未知退出码、路由变化和已结项任务拒绝恢复。登记纠正不扣独立审核预算。Luna 五倍复杂度三轮对照未证明团队模式更省资源或质量更高：总 token 为单会话的 3.61 倍，未缓存用量为 4.34 倍，团队独立结项 4/9。已知限制及统计口径见 [发布说明](RELEASE_NOTES.md)。

0.40.54 区分“已启动、正在自绑定”与启动未知/失败：核对父会话、目录、预留路径和当前原生运行状态后有界等待，不因尚无任务 turnId 提前结束 Leader；不授予执行或验收权限，也不重派成员。异常、终态和不安全启动继续阻塞并保留历史。

0.40.53 统一等待入口提示：协调摘要、轻量状态、超时回执均指向实际暴露的 team_leader 路由及明确操作，不再把内部 wait_team_event 名称当作独立可发现工具。缓存等待仍合并真实事件，无需为等待重读状态或重跑验证。

0.40.52 统一首次绑定、绑定重放与并发完成的 bootstrap 响应，均返回完整缓存报告入口和模板；同一绑定只登记一次。

0.40.51 缓存成员原始绑定与回执请求，报告只填写事实字段，避免长任务结束后抄错启动凭据。已拒绝的原生交付可明确预检并恢复：核对原调用、完整输入指纹、工作目录与宿主退出码，保留原报告和中断历史，不重跑测试、不扣审核预算；独立审核继续强制。修复新版本登记异常未持久化造成的重复空转。

0.40.49 对于预留后未发出启动的任务，核对完整宿主调用历史与两次成员索引，再返回原始派发包；已发起但未确认的调用仍不重发。面板区分“尚未启动”和“未知”。阶段交接后的空启动恢复保留原检查点与有效命令证据。

0.40.48 将启动与恢复校验落到宿主真实记录：启动前拒绝配置冲突，绑定前核对干净子会话及冻结模型路由；初始绑定不再依赖手抄任务标记。启动被拒时面板显示具体原因，已结束且未执行的 bootstrap 可在核对原生终态和候选未变化后安全恢复，保留原会话与失败记录，不扣代码返工或审核预算。独立审核按当前任务合同登记，后续任务观察单独归属；范围或格式纠正留在原审核轮次，复用已有有效测试。真实缺陷、未知执行和变化后的候选仍保持阻塞。

0.40.42 转向可靠交付与审核质量：无运行成员且无可执行路径时，返回具体合同、依赖或尝试上限阻塞，不再空等。新编译审核的一次性问题清单必须关联当前合同和源码/原日志证据；建议不触发返工，合同问题无论严重度均需明确关闭。局部返工保留完整合同、有效上游、原报告与中断历史。显式 `executionMode: "auto"` 按业务复杂度选择执行方式，合适的单个低/中复杂度任务由 Leader 执行、原生成员独立审核；显式路由、严格风险及复杂任务保持原生成员。新增实际登记的一审通过率、返工和闭环指标，不把这些指标宣称为代码正确率或质量提升百分比。

0.40.17 减少登记与总结往返：认证后的审核启动同步提供对应原始交付、命令页与输入核对；成功结项返回有限摘要和证据入口，Leader 不再为总结读取整队历史。完整报告、失败、中断和独立审查保留；摘要是验收时回执，不替代源码审查或未来候选验证。节省幅度需用真实 Luna 对照测量。

0.40.16 统一 Codex 各派发入口：预留唯一轮次后只发送启动凭据，成员绑定成功才领取工作指令。面板区分关联中、关联超时与额外会话；缓存用量按当前绑定重投影，保留全部成本与历史证据。验证命令支持已确认 POSIX 工作目录内的字面参数引号等价，避免同一已完成测试因单/双引号差异被拒绝。

## DSH npm 分发

DeepSeekHarness 的正式安装入口为 npm 包 [`agent-team-deepseek-harness`](https://www.npmjs.com/package/agent-team-deepseek-harness)。本次版本为 `0.40.57`，发布后可通过 `dsh plugin --profile <existing-profile> add agent-team-deepseek-harness@0.40.57` 安装。包包含编译后的原生入口和 MCP 服务，使用包名加载，DSH 插件管理器自动登记 bundle。ZIP 仅保留为开发暂存产物。

发布准备命令为 `npm run build`、`npm run package:dsh`、`npm run verify:dsh-package`。最后一项在隔离的 DSH_HOME 中使用真实 `dsh plugin add` 安装生成的 `.tgz`、核对自动 bundle 登记、配置组合、导出和六个原生工具，全程不启动模型。登录并完成 npm 发布认证后执行 `npm run publish:dsh`，发布脚本核对同一包的安装证据与远端 integrity，拒绝覆盖不同内容的已有版本。npm 接受上传后立即保存回执；索引尚未可用时有限等待，不重复上传。等待结束后仍未可用，执行 `npm run verify:dsh-published` 继续只读核验。

## 0.32.0 初始化证据关联与等待成本

环境初始化链支持显式绑定到当前合同命令：核对原报告完整声明、原生 commandId、工作目录、真实成功退出码和未变输入，保留中断及审查原文。仅支持字面量初始化与 && 链，失败屏蔽、管道、动态命令和不透明脚本仍不能满足验收。旧准备记录缺少预执行指纹时明确提示使用原报告 manifest，不补造历史证明；manifest 全部文件哈希仍核对，输入根按原声明的源码/配置范围选择。

等待增加跨调用 waitCursor 和可直接复用的 continuationArgs，普通进度不触发状态/schema 重读；默认等待55秒，协调调用设置 functions.exec yield_time_ms=60000，减少中途返回的模型往返。阶段交接建议提前至60000当前输入 token 或30次命令，仍只在明确完成边界交接，不强制清空、降档或重跑。插件不能消除宿主有界等待产生的全部空闲模型轮次。

## 0.28.0 执行观察与状态稳定性

原生生命周期观察补充 MCP 工具与上下文压缩完成的公开事件元数据，只读类型、身份与时间，不读取工具结果、压缩内容或推理。面板统一任务、成员与执行历史的状态说明；记录延迟不授权验收、结算、重派或重复运行。

## 工作方式

- 团队确认：新团队先确认目标、成员和职责，确认后 Leader 拆分具体任务与独立审查，无需逐项确认；支持面板编辑或聊天确认；修改后旧确认失效。明确“直接做”可立即执行，普通追加沿用授权；新增岗位、扩大范围和提高预算单独确认，原团队继续运行。
- 同一项目保留一个团队，新任务追加给现有成员；需要新岗位时直接追加成员，重建由用户主动触发。
- 使用 `add_team_members` 追加岗位（活跃人数最多 8），按需模式等首项任务就绪再创建；先用 `add_team_tasks` 分配任务。空闲且无未完成任务的成员可 `remove_team_member`，记录仍保留；`reassign_team_task` 改派等待/阻塞任务，旧轮次归属和重试预算不变。
- 岗位与当前执行会话一对一，命名采用「项目-角色」；已结算任务之后创建干净会话，原线程保留用于历史审计。
- 新团队默认按需创建成员，首个就绪任务携带完整交接包；后续复用同一原生线程。已有团队保留原启动方式。
- 初始面板支持成员和目标编辑，自动读取宿主模型及档位；具体任务在组建确认后拆分，扩展面板保留任务和依赖编辑；并发与预算按需展开，保存后重新确认版本。
- 停止覆盖初始化轮次：stopping → 核实实际终态 → halted；明确原因才能恢复，重试任务单独选择，历史与预算保留。
- Leader 拆解、派发、停止、处理异常与最终结项；普通独立审核由插件校验登记；真实成员可领取自己的就绪任务、报告进度和暂存交付，宿主终态仍须核实。
- 成员共享当前项目，按任务按需读取，不复制完整项目，没有 128MB 快照启动门槛。
- 任务预留、执行、提交、独立审查、最终验收分别记录，历史轮次不会冒充当前交付。
- 可声明阶段、写入/排除范围、验证命令与目标覆盖合同；需求独立验收后再实施。合同验收要求逐项 PASS 和宿主记录的成功命令；改动范围根据成员申报核对，不宣称自动发现所有文件改动。
- 可选择 `autoRepair`，由 Leader 确认退回后生成修复任务和独立复审，重定向下游依赖并保留原证据。问题 ID 跨轮追踪，严重问题需独立证据关闭；审查轮次超限暂停并升级给 Leader。
- 状态先显示、详情后台加载；面板预览限制 256 KiB，完整证据按需读取。实际执行中轮询目标间隔 250ms，已结束待接收的执行降为 1s。任务标签统一编号，依赖卡片 160×76px。
- 原生会话导航使用宿主 openLink 和已验证的 codex 会话深链接；不依赖模型或消息能力。失效请求不打开旧目标，未绑定执行的任务不借用成员的其他会话。宿主接收链接与实际页面呈现分别记录。
- 执行完成前显示公开进度、命令输出和按轮次统计的 token 用量；不会展示隐藏推理。
- 成员持久收件箱、接续包、重试上限和有界工作流由 Leader 控制，工具回执与已读分别记录。
- 支持完整任务模板或仅保存岗位与约束的动态规划模板；宿主模型目录验证显式路由，默认档位随计划冻结。
- 合同修订记录前后值与版本，使旧下游证据失效；已通过验收的合同冻结。压缩前置摘要，保留完整验收条件。
- 写入成员可选择 Git worktree；已独立验收候选经冲突预检后暂存合并，由 Leader 验证并提交。
- 任务号/状态搜索、公开报告导出、时延诊断和校验分卷保留长团队历史。

## 开发

需要 Node.js 22+，打包需要 Python 3，浏览器检查使用 Chrome。

```powershell
git clone https://github.com/wapearoudy/codex-agent-team.git
cd codex-agent-team
npm ci
npm run build
npx playwright install chrome
npm test
npm run validate
npm run package
```

构建输出到 `plugins/team-workspace-probe/dist/`，ZIP 输出到 `artifacts/`，生成文件不提交。GitHub Actions 在 Windows 上执行构建、回归、校验和打包。

## 本地使用

插件身份为 `team-workspace-probe`。构建并通过检查后运行 `node scripts/install-plugin.mjs`，登记本地来源并调用官方安装命令。已有来源会保留备份，不直接修改缓存或强制重启宿主。详细步骤见 [开发与安装说明](docs/DEVELOPMENT.md)。

Windows 默认发现当前用户安装的官方 Codex Desktop 可执行文件；自定义安装位置可设置 `TEAM_WORKSPACE_CODEX_BINARY`。仓库不包含开发者本机路径、登录信息或真实团队记录。

## 实际边界

执行由 Leader 所持有的原生协作工具控制，MCP 服务不能替代这些工具。视图读取宿主持久化快照，轮询间隔不是端到端时延承诺。成员写入范围属于任务约束和冲突调度，不替代文件系统沙箱。

浏览器/协议检查与真实 Desktop 原生执行分别验证；自动检查通过不代表未执行的宿主联调已经通过。原生会话导航不支持指定轮次锚点，历史轮次在面板中回看。

见 [架构与数据边界](docs/ARCHITECTURE.md)、[开发与安装说明](docs/DEVELOPMENT.md) 和 [插件使用协议](plugins/team-workspace-probe/skills/team-workspace/SKILL.md)。
