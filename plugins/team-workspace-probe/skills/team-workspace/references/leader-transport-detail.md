# Team Workspace 0.40.45

The current chat is Leader. The plugin stores contracts and observes native work; it never starts models or wakes an ended Leader. Internal communication uses native agent messages, completions and saved checkpoints, never injected chat messages. Viewing a panel does not start work. Panel sync may register authenticated terminal deliveries and valid independent PASS, never dispatch, decide exceptions or close the goal.

SourceInputs contain real selected pages. Use nextReadBatch or read_team_materials to fetch missing source/log pages in one bounded call; exact continuations and omitted selections remain explicit. QA requiredCommandOutcomes.savedLog includes the exactly registered original validation log and native exit. Inspect it once instead of fetching empty redirected stdout first. Missing/changed logs are not PASS.

Pending dispatch is the next action, not a running member. Invoke each exact nativeAction directly before waiting. An unconfirmed launch reply requires one native identity reconciliation; never send the reservation twice or poll it as active work. Wait entries are withheld until launch/start actions are resolved.

## Wait and close

After native dispatch run the returned waitInvocation verbatim in functions.exec. It is self-contained even when the preceding tool was called directly and functions.store is empty. Every ordinary next_team_step advancement and unchanged timeout returns this bounded entry; no directory/describe/state read or load-only call is needed. It saves teamStep itself and reuses only this team's exact continuationArgs. Older clients may retain the first waitProgram as teamWaitProgram; never reconstruct a missing program or reuse another team's cursor.

If exec returns a running cell, resume the SAME cell with functions.wait and yield_time_ms=55000; do not poll it at 1s/10s intervals or read team state in parallel. It coalesces up to four 55-second unchanged waits with progress notices, preserving continuationArgs and waitCursor, and stops on business dispatch, exception, control or terminal. Do not reread state/schema/inbox for a timeout. Older packets use next_team_step with exact continuationArgs and functions.exec yield_time_ms=60000. Keep Leader active; unknown is not completed. Never dispatch paused/stopping. requiresLeaderAction=true means resolve that saved action once using original evidence. startup-failed/waitBlocked means a failed startup, not waiting: show the actual error, preserve the launched reservation, no automatic respawn or false unstarted release. Missing member tools are one internal blocker before work, without repeated discovery.

finishReady=true explicitly opts into final closure inside next_team_step; keep it in continuationArgs. Without it, call finish_team once with returned finalizationArguments. The gate rechecks goal coverage, findings, unchanged exact candidate and required integration. On failure inspect only its concrete exception. A successful completion receipt has accepted native/task identities, report summaries, host verification exits and artifact paths: report it directly without shell commands, hashes, exports, reviews/tests for bookkeeping. terminal=true/nextAction=return-result ends coordination. Archive/export only when requested; history remains intact.

A token-budget-limit receipt ends the current Leader turn with its explicit unfinished state. It supplies no continuation or wait program. Do not retry waits, raise limits or dispatch replacements. Already active native members retain their work; no synthetic completion or interruption is recorded. Handle real terminal events or an explicitly authorized budget change separately. Cached wait transport also stops on exhausted/unverifiable usage from older receipts.
