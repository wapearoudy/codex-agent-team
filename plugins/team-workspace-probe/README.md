# Team Workspace 0.15.1

0.15.1 修复停止通知失败提示被较晚的详情刷新清空的问题。提示与本次停止请求绑定，刷新及语言切换保留失败说明；成员终态核实后展示已停止事实。

0.15.0 新增组建后的角色目标编辑。成员卡片铅笔图标与管理入口共用编辑器，可查看原目标、修改说明和最近修订；保存直接写入原团队，不发消息、不启动或打断成员。新目标用于后续派发，已预留/运行任务和历史轮次保留原目标快照。刷新不覆盖输入，并发修改与未知保存可核对后重试。首次修改使用 0.15.0 数据保护，旧连接拒绝写入。

0.14.6 将面板详情与原生会话跳转分离：任务标签、列表、依赖节点只打开面板详情；导航按钮经归属校验后直接用宿主 openLink 打开 codex 会话链接，不发主 agent 消息、不启动模型。历史任务按真实执行会话定位，未绑定任务不借用其他会话。失败只留在面板显式重试；链接被宿主接收不等于页面已呈现或定位到轮次。旧版导航请求继续兼容读取。

0.14.5 将成员卡片的打开会话、查看任务按钮收为图标，与任务标签同行。悬浮 650 毫秒后显示功能说明，键盘聚焦立即显示；不可用按钮说明未绑定原因。提示支持 Escape 关闭、中英文与窄屏，自动刷新不重置延时或重新打开已关闭提示，保留原导航与详情操作。

0.14.4 加强成员任务标签与依赖图的状态配色：已验收为绿、执行中为蓝、待验收为紫、待派发为琥珀、受阻或失败为红，取消保留灰色。任务标签使用更明显的底色，依赖节点增加同色边框与侧边色条；浅色、深色与选中状态均保留清晰区分，布局与任务操作保持原有行为。

0.14.3 修复宿主将验证命令记录为 `/bin/zsh -lc '…'` 等 shell 包装时的验收误判。只解包标准 sh/bash/zsh 的字面量参数，完整脚本保持精确比较；追加操作、动态外层展开、失败或未结束的命令不能充当成功证据。显式独立验收与最终登记都会从当前 attempt 保存的原始宿主命令重新核对，旧版缓存的误判不要求重派成员或重复执行任务；原始命令、合同和历史保持完整。

0.14.2 按浅色风格重排工作台：突出目标与进度，先成员后任务，以排版、分隔线和真实状态区分主次；任务区用简短提示展示“当前关注”。任务支持搜索、详情及关闭返回；依赖节点点击或按 Enter 查看，经过时不弹出详情。运行说明收至下方；工作区阻塞和验证限制仍主动展开。macOS 自动定位官方 Desktop 自带的 Codex 程序，无需把本机路径写入插件清单。

0.14.1 简化面板交互：停止与继续直接操作，原因自动留痕；可选说明、失败重试与通知设置按需展开；已确认计划默认收起。

0.14.0 修复成员跨任务复用线程造成的旧上下文累积：核实原生终态后，下一次派发使用干净会话和 fork_turns=none，岗位、worktree、历史线程、用量与独立审查归属保持完整。启动结果未知或活动轮次不替换。完整派发提示纳入 contextChars 硬预算，超限原子回滚预留；历史证据只按需读取。

0.13.0 增加 Leader/成员按需操作入口、计划批准后的持久工作流通知、退回聊天修改、运行期间岗位/任务管理、合同历史、归档浏览、模板维护和中英文切换。默认继承模型保存 model/provider/effort 快照，未知字段不猜测。通知去重，未知送达只显式重试；原生成员执行与独立验收仍由当前 Leader 负责。


0.11.0 增加完整计划确认流程：复杂新团队先审阅一次目标、分工、任务与验收，面板可编辑并保存新版本，也可在聊天中确认。明确要求直接执行可跳过，已有团队普通任务沿用授权；新增岗位、扩大范围和提高预算先暂存为变更提案，确认前原团队继续。确认绑定版本/hash，重复请求去重，取消保留历史。确认不代表验收，插件仍不直接启动模型。新记录拒绝 0.10.0 旧连接写入。

当前 Codex 主会话担任 Leader，宿主原生 subagent 接受任务。插件提供任务依赖、预留、真实成员绑定、执行记录与独立审查，内嵌面板仅展示。

0.10.0 增加可选质量合同（阶段、验收条目、范围、验证命令与目标覆盖）、需求验收门禁、严重问题台账和修复复审链路。configure_team_policy 的 autoRepair 默认关闭，maxReviewRounds 默认 3；Leader 确认结构化退回后创建新修复和独立复审，重定向后续依赖，原证据保留，超限暂停升级。合同 PASS 必须有本轮宿主成功命令，改动路径基于成员申报核对。新增 reassign_team_task / remove_team_member；改派前确认终态，移除前无未完成任务，历史执行者、消息、检查点和 token 归属不随任务归属改变。活跃成员上限 8，移除释放名额但 ID 不重用。升级后须重启宿主再使用新工具，避免旧驻留服务继续控制新版团队。

## 本地开发

源码 `src/`，`npm run build` 生成自包含 stdio MCP 服务和视图。`npm test` 运行回归。通过 `scripts/package.py` 打包、`scripts/stage-upgrade.py` 更新本地来源，再用官方 `codex plugin add team-workspace-probe@fusion-local` 安装。不要直接修改缓存。

这是实验开发版本，不能将协议测试当作 Desktop 实际模型联调。原生工具必须由当前 Leader 调用，插件 MCP 服务不能直接调用模型所持有的 collaboration 工具。没有原生工具时明确阻塞，不切回另一执行宿主。公共源码的架构与验证边界见 docs/ARCHITECTURE.md 和 docs/DEVELOPMENT.md。
