# Team Workspace 0.8.6

当前 Codex 主会话担任 Leader，宿主原生 subagent 接受任务。插件提供任务依赖、预留、真实成员绑定、执行记录与独立审查，内嵌面板仅展示。

0.8.6 准备公开源码维护：清单移除开发者个人可执行文件路径，沿用现有官方 Desktop 自动发现与环境变量覆盖；构建、回归和包校验可在新克隆中运行。

0.8.5 缩小依赖/并行任务卡片至 160×76px，收紧卡片间距并同步连线。卡片使用同一顺序任务号，标题单行，悬停或点击查看完整内容；保留状态、负责人和原任务标识路由。

0.8.4 将 Leader 与进度合为顶部卡片，成员的任务号、导航操作和历史轮次集中在同一区域。任务详情与成员执行合为一个详情区，位于成员旁或成员下方、依赖图之前；宽面板并排，窄面板上下排列。保留历史轮次、阅读位置、任务依赖、真实执行和权限边界。

0.8.3 成员下「队长派发」标签只显示团队内的顺序任务号 t1、t2…；各成员共享同一编号序列，悬停可查看原始任务标识、标题和状态，点击仍定位对应任务。编号按团队任务登记顺序生成，追加任务不改变已有编号。

0.8.2 状态、任务与验收进度在收到 state 后先更新，完整历史和交付独立加载；只保留一个在途详情请求和最新待加载目标，旧响应不能覆盖新轮次或新状态。面板按 detailToken 复用刚核对的相同快照，避免状态后重复观察成员；仍核对当前项目与 revision，缓存不更新观察时间。运行时目标间隔 250ms，空闲/空面板 1s，隐藏 10s，实际读取不另加整个间隔；导航回执不阻塞轮询，状态读取不重叠。可见/聚焦立即同步。此为轮询和界面改进，不保证宿主事件持久化或实际工具执行在 250ms 内完成。

0.8.1 修复早期消息未知 turnId 导致 Message identity mismatch：原任务/attempt/成员/线程仍严格核对，未确认的空 turnId 不阻止重绑和终态接收。只有原轮次的精确公开消息回执才能补全 turnId 并记录审计；非空冲突和旧轮次误认仍拒绝。保留已有团队、消息 ID、记录和独立验收条件，不重发消息或自动验收。

- 项目由当前宿主线程绑定，不选择目录或重填目标。
- 成员共用项目，按需读取。没有整项目快照、依赖复制或 128MB 启动门槛。
- Leader 使用原生 spawn/followup/message/interrupt/wait；插件不另起模型调度器。
- bind 验证原生父线程、cwd、唯一任务标记；同一角色接续同一原生成员。
- 预留、执行、提交、独立验收、Leader 最终验收分开记录。
- 视图是持久化宿主执行快照，可能滞后，不是实时事件订阅。
- 共享项目写入范围由成员遵守，派发检查冲突；不宣称文件系统隔离。
- 旧隔离团队只保留读取、停止、历史写回/恢复，不再启动旧调度器。

## 本地开发

源码 `src/`，`npm run build` 生成自包含 stdio MCP 服务和视图。`npm test` 运行回归。通过 `scripts/package.py` 打包、`scripts/stage-upgrade.py` 更新本地来源，再用官方 `codex plugin add team-workspace-probe@fusion-local` 安装。不要直接修改缓存。

这是实验开发版本，不能将协议测试当作 Desktop 实际模型联调。原生工具必须由当前 Leader 调用，插件 MCP 服务不能直接调用模型所持有的 collaboration 工具。没有原生工具时明确阻塞，不切回另一执行宿主。公共源码的架构与验证边界见 docs/ARCHITECTURE.md 和 docs/DEVELOPMENT.md。
